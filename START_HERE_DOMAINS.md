## 5. What the code does

`get_domain_id(x, y, K, field_width_um)` divides the width into K equal physical
strips. IDs go from 0 to K-1, left to right. The domain depends only on x. An exact
internal boundary belongs to its right-hand strip; x equal to the full field width
is invalid. Both coordinates must be finite and nonnegative.

The mathematical rule is `min(floor(x*K/W), K-1)`. Floating-point division can put
an exact boundary on the wrong side, or round a nearby point into the next domain.
The implementation compares x with implicit boundaries using binary search instead.
Boundary i is represented as `W*i/K`, without snapping nearby values with an epsilon.
Tests cover the immediately adjacent representable floats on either side.

`assign_cell_types(...)` copies your positioned cells, assigns center domains, then
samples one type per cell using that domain's probability row and the supplied shared
NumPy Generator. All original columns and the index survive. Cell radii do not affect
assignment. Validation completes before any random draws; the function creates no seed.

Probability rows must be finite, nonnegative, and sum to 1 within absolute tolerance
1e-8 with no relative tolerance. Accepted numerical roundoff is normalized on a private
copy before sampling. Probabilities must be real-valued; complex matrices are
rejected before conversion. Cell-type names must be unique nonblank strings in an
explicit order, such as a list or tuple. Sets, frozensets, and mappings are rejected
to preserve the probability-column meanings.

`build_domains_dataframe(...)` labels every supplied square by its center using the
same scalar function. It returns exactly `square_id,domain`, preserving order and index,
with string domain labels. IDs must be unique nonblank strings. No cells or transcripts
are needed, so unoccupied squares also receive labels.

All three functions operate on data in memory. File export is demonstrated in the
notebook and belongs to the team's I/O component in the full simulator.
